# Карта обменников — правила работы

Главный источник требований — [SPEC.md](SPEC.md). Прочитать целиком в начале каждой сессии. Ссылаться на требования по номерам FR-N.

## Как работаем

- Идём строго по разделу SPEC.md «План разработки по шагам», по одному шагу за раз.
- В конце шага — остановка: что сделано + как выполнить «Проверку» шага (что открыть, куда нажать, что должно быть видно). Следующий шаг — только после слова «дальше».
- Если спецификация расходится с реальностью (нет поля у источника и т.п.) — не придумывать обход молча: описать проблему и предложить 2–3 варианта.
- Только бесплатные сервисы и библиотеки. Если что-то требует оплаты или привязки карты — сначала спросить.
- Аккаунты (GitHub, Vercel, Neon) пользователь создаёт сам. Когда нужен вход — назвать команду (например, `gh auth login`, `npx vercel login`) и ждать.
- Действия в терминале — по одной команде за раз, с пояснением, что должно появиться; следующую — после ответа пользователя.
- Все тексты интерфейса — на русском, в отдельном файле локализации (позже добавится польский).
- Коммит после каждого шага; в сообщении — номер шага и FR, например `Шаг 3: адаптер kantor.live (FR-14, FR-21)`.
- Внешние сайты-источники не трогать чаще, чем нужно: пауза ≥ 1 с между запросами, честный User-Agent, не чаще раза в 15 мин на город; API Сбера — не больше 2 запросов в минуту.

## Ключевые решения из спецификации

- Стек — сервисы, где у пользователя уже есть аккаунты (как в её fin-tracker / travel-tracker): Vercel (fra1) для PWA и функций `/api/*`, Neon Postgres + Drizzle, GitHub Actions только для еженедельной пересборки списков и координат. Курсы собираются только по запросу (открыли приложение → данные города старше 15 мин → отдать старые с «обновляется» и обновить в фоне), расписания для курсов нет. Cloudflare не используем.
- Структура: `app/` (PWA, Vite + TypeScript, Leaflet + leaflet.markercluster), `api/` (функции Vercel), `collector/` (сбор), общий код адаптеров. Телефон никогда не ходит к источникам курсов напрямую.
- Таблицы: `exchangers`, `rates` (с `confirmed_at`), `city_fetches`. API: `POST /api/exchangers` {bounds} — зона поиска = видимая область карты, радиуса нет (решение 08.10.2026) (координаты только в теле — адреса попадают в журнал Vercel), `POST /api/favorites` {ids}, `/api/currencies?country`, `/api/health`.
- Источники: PL — JSON карты kantor.live (основа), marketportal.pl (ширина), kursarz.pl (свежесть, kantory сами вносят курсы); zlata.ws — нет (капча); BY — myfin.by `/currency/<город>` (основной), API Беларусбанка (приоритетный для своего банка), kurs.onliner.by (координаты Минска). Сбер API, XML МТБанка (robots запрещает `*.php`) и rates.fm не используем. Каждый источник — отдельный адаптер к общей модели. Правила склейки 1–8 в SPEC.md.
- В Польше только kantory, без отделений банков.
- Курсы хранятся как «местная валюта за 1 единицу иностранной»; 0/пусто = нет этой стороны курса (проверять покупку и продажу отдельно).
- «Покупаю» = курс продажи обменника (sell), «Продаю» = курс покупки (buy) (FR-12).
- Открыт/закрыт — по местному времени страны (Europe/Warsaw, Europe/Minsk), не телефона (FR-21).
- Карта: тайлы OSM, поиск Photon (запасной Nominatim).
- На телефоне всё в localStorage, каждое обращение в try/catch.
- Приватность: координаты пользователя не сохраняются и не логируются; без аналитики.
