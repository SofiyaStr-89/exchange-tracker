# Беларусь собирается целиком, Польша — только частично

Лучший бесплатный путь разный для двух стран. **В Беларуси почти полную картину дают четыре бесплатных источника без ключей.** Страница `myfin.by/currency/<город>` одним запросом отдаёт все отделения всех банков города: по Минску это 530 точек 22 банков, у каждой своё время курса и JSON с курсами. Официальные API Беларусбанка (`kursExchange` + `filials_info`) дают курсы, координаты и часы работы его 1102 точек одним вызовом на всю страну. XML МТБанка добавляет координаты его отделений, а kurs.onliner.by — координаты почти всех минских точек. **В Польше полной картины не существует ни у одного источника.** Курсы в интернете публикует примерно четверть–треть kantorów. Поэтому база — JSON карты kantor.live, к нему добавляются zlata.ws (12 крупнейших городов, у каждого kantoru своё время курса) и marketportal.pl (142 города, часы работы, много валют). Координаты недостающих точек берутся геокодированием через GUGiK/Nominatim. Всё это укладывается в бесплатный Cloudflare Workers + Cron + D1, но с двумя оговорками. Во-первых, связывает не лимит запросов, а **10 мс CPU на один запуск**: страницы myfin (2,1 МБ) и onliner (2,9 МБ) придётся разбирать в отдельных запусках через Queues, а при нехватке CPU — переносить в GitHub Actions. Во-вторых, **недоступность .by-источников с серверов вне Беларуси до сих пор не проверена**, и это главный риск всей архитектуры. По сравнению со SPEC.md меняется следующее. В Беларуси вместо 21 страницы банков на город запрашивается одна страница города. API Сбера и rates.fm уходят из MVP. Беларусбанк получает координаты из собственного API, а в Польше появляются два новых источника курсов.

## Польша: у четверти kantorów есть свежий курс, остальные нигде не публикуют

Потолок покрытия задаёт не выбор источника, а сам рынок. В справочнике kantorymapa.pl 3769 стационарных kantorów в 746 городах, из них **249 в Варшаве**. Курсы там при этом показываются по NBP, а не настоящие курсы обменников ([kantorymapa.pl](https://kantorymapa.pl/)). Агрегаторы курсов по Варшаве знают меньше: kantor.live — 80, zlata.ws — 61, marketportal.pl — 57, quantor.pl — 29 ([zlata.ws](https://zlata.ws/pl/kantory/warszawa/), [MarketPortal](https://marketportal.pl/kantory/warszawa), [Quantor](https://quantor.pl/kantory/warszawa.html)). Названия у этих агрегаторов в основном совпадают (Redar, Respol, Zawisza, Pod Dębami, Saska). Похоже, все они собирают курсы с одного и того же круга kantorów, у которых есть сайт с курсом. zlata.ws прямо просит kantory прислать «stronę internetową z kursem wymiany» ([zlata.ws](https://zlata.ws/pl/kantory/warszawa/goclaw/)). Значит, **реально достижимо около 60–80 варшавских точек со свежим курсом из ~250**. Это оценка по пересечению названий, а не измерение. Сети почти ничего не добавляют. Крупнейшая подтверждённая сеть, Tavex, — это **15 точек в 9 городах** ([tavex.pl](https://tavex.pl/)), а в OSM только у 8 из 1645 kantorów есть тег `brand` (собственный запрос к Overpass 08.10.2026).

Лучшее из новых находок — **zlata.ws**. В Варшаве **59 из 61 строки датированы 08.10**, вся страница — обычная серверная HTML-таблица, и одного запроса хватает на весь город ([zlata.ws](https://zlata.ws/pl/kantory/warszawa/)). Есть и неясность со временем. В списке у Centrum Gocław стояло 14:04, а на его собственной странице минутой позже — «Ostatnia aktualizacja: 08.10.2026 в 16:04» ([zlata.ws Gocław](https://zlata.ws/pl/kantory/warszawa/goclaw/)). Скорее всего, в списке время UTC, а на странице kantoru — варшавское, но пока это догадка. **marketportal.pl** закрывает ширину: 142 города, часы работы по дням, розничные и оптовые курсы. Его метка «Ostatnia aktualizacja … 2026-10-08 15:49» одна на весь город ([MarketPortal](https://marketportal.pl/kantory/warszawa)). Скорее всего, это время, когда marketportal собрал курсы с сайтов kantorów, а не время, когда сам kantor их поменял. Поэтому устаревший курс там может выглядеть свежим. **kantor.live** остаётся единственным источником, где координаты, часы и время курса по каждой валюте приходят в одном JSON. Но свежий курс там только у 15 из 80 варшавских kantorów (recon/REPORT.md, шаг 1). quantor.pl интересен тем, что kantory сами обновляют курсы через панель. Сервер отдаёт только 7 записей, остальные подгружаются по XHR, адрес которого ещё не найден ([Quantor](https://quantor.pl/kantory/warszawa.html)). Это кандидат на потом, не для MVP.

Координаты и часы придётся собирать отдельно. В OSM Польши 1645 объектов `amenity=bureau_de_change`. Часы работы указаны у 36,5% из них, название — у 56%, улица — у 24% (собственный запрос к Overpass, osm_base 2026-10-08T14:05Z; [taginfo](https://taginfo.geofabrik.de/europe:poland/api/4/tag/stats?key=amenity&value=bureau_de_change)). Значит, OSM годится как запасной источник координат, но не как основной список. Для польских адресов лучше всего подходит официальный геокодер GUGiK по адресным точкам PRG ([QGIS plugin](https://plugins.qgis.org/plugins/geokodowanie_adresow/), [geoportal OpenLS](https://www.geoportal.gov.pl/pl/usluga/usluga-openls/)). Публичный Nominatim разрешает разовую пакетную задачу со скоростью 1 запрос в секунду и кэшированием. Регулярные скрипты ограничены 4 запросами в минуту ([OSMF Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/)). Реестр kantorów NBP формально открыт, но это форма поиска по названию фирмы или NIP, а не набор данных для скачивания ([kantor.nbp.pl](https://kantor.nbp.pl/)).

## Беларусь: одна страница города заменяет 21 запрос, а у Беларусбанка есть координаты

Главная перемена по сравнению с разведкой шага 1 такая. **Страница `myfin.by/currency/minsk` за один GET отдала 530 отделений 22 банков.** В каждой строке есть стабильный ID отделения, адрес, **своё время курса** (`ic-update-time` 17:07) и скрытый JSON вида `{"USD":{"buy":3.02,"sell":3.07,"multiplier":1},…}` ([myfin.by/currency/minsk](https://myfin.by/currency/minsk)). Курсы свежие: в снимке почти все времена попали в окно 17:01–17:08 при запросе около 17:10. На главной странице города только USD, EUR и RUB. PLN и CNY живут на отдельных страницах валют: `/currency/pln` вернула 273 минских отделения 14 банков с курсом за 10 PLN ([myfin.by/currency/pln](https://myfin.by/currency/pln)). Координат и часов на странице города нет. robots.txt разрешает `/currency/<город>` и запрещает любые адреса с query-строкой ([robots.txt](https://myfin.by/robots.txt)). Под этот запрет попадает и `/ajax-map/map-json?mapObjectId=…`, поэтому вариант B из решения №3 отчёта шага 1 закрыт.

Курсы одного банка в разных отделениях действительно отличаются. Это видно по числу разных наборов (USD, EUR, RUB) у банка в Минске. У Беларусбанка, Белгазпромбанка и ВТБ на всех отделениях один набор, у Сбера 16 разных на 22 отделения, у БСБ — 19 на 36, у РРБ — 16 на 26 ([myfin.by/currency/minsk](https://myfin.by/currency/minsk)). Значит, модель «один курс на банк в городе» дала бы неверную подсветку лучшего, и нужны данные по каждому отделению.

**Беларусбанк — ценный официальный источник.** `filials_info` присоединяется к `kursExchange` по `filial_id` один к одному: в Минске нашлись все 137 из 137. У каждой точки в `filials_info` есть координаты, часы в трёх форматах и флаги услуг, в том числе `usl_konversiya_foreign_val` ([filials_info](https://belarusbank.by/api/filials_info?city=%D0%9C%D0%B8%D0%BD%D1%81%D0%BA)). Тем самым снимается пункт из отчёта шага 1 «❌ Координат нет». Остаются две особенности. Все 1102 строки имели `kurs_date_time` = «2026-10-07 17:20:00» на момент запроса 08.10 в 17:08. Это время установки курса, и по FR-24 действующий курс ошибочно попадёт в устаревшие. Кроме того, единицы в ответе не указаны: PLN и CNY даны за 10, RUB и CZK за 100. Это совпадает с `Cur_Scale` Нацбанка, и масштабы лучше брать из [NBRB API](https://api.nbrb.by/exrates/rates?periodicity=0), а не держать зашитой таблицей. У других банков официальных лент по отделениям не нашлось, кроме МТБанка и Белгазпромбанка. Старая лента Белагропромбанка `CashExRatesDaily.php` отдаёт 404 ([Kursownia](https://github.com/MaksimSurmach/Kursownia/blob/9f98fe921875a501df5ce69aee6893d80df0b5e4/Kursownia/rates/rate_getter.py)). Так что для Приорбанка, Белинвестбанка, БНБ, Сбера и остальных единственный реальный путь — myfin.

## Рекомендуемые комбинации и ожидаемое покрытие

**Беларусь, курсы.** Основа — myfin `/currency/<город>` каждые 15 минут для Минска и по запросу для остальных городов. Страницы `/currency/pln` и `/currency/cny` можно забирать раз в 30–60 минут. Для своих банков приоритет у официальных лент. Беларусбанк забирается одним общим вызовом `kursExchange` на всю страну каждые 15 минут, и это сразу покрывает 585 населённых пунктов. МТБанк — одним вызовом `currxml`. Данные Белгазпромбанка myfin уже покрывает, а `courses.xml` можно подключить позже ради курсов, зависящих от суммы, после ручной привязки 46 названий отделений. **Ожидаемое покрытие в Минске — все ~530 точек 22 банков**, со свежестью не хуже 30 минут: так myfin заявляет о своих обновлениях ([myfin.by/bank/mtbank/currency](https://myfin.by/bank/mtbank/currency)). Фактически в снимке было около 10 минут. В регионах Беларусбанк и myfin дают все банки, которые там вообще есть.

**Беларусь, координаты и часы.** Порядок такой. Для Беларусбанка — `filials_info`. Для МТБанка — `currxml`. Для остальных банков в Минске — onliner, склейка с myfin по нормализованному адресу и названию отделения. Для регионов и непривязавшихся точек — разовый обход страниц отделений myfin `/bank/<банк>/department/<id>`. По шагу 1 на этих страницах есть центр карты и часы. Минск — это ~530 запросов один раз, дальше только новые ID, раз в месяц. Запасной путь — OSM и геокодер. Часы будут структурированными у Беларусбанка, у остальных взяты со страниц отделений myfin, у МТБанка неизвестны до обхода.

**Польша, курсы.** Основа — JSON kantor.live: список, координаты у 64% точек, часы, время по каждой валюте. Поверх него идут **zlata.ws** (12 городов, обновление каждые 15 минут, время по каждому kantoru) и **marketportal.pl** (142 города, раз в 30–60 минут, потому что метка у него одна на город). Отдельный адаптер **Tavex** стоит делать только после того, как в devtools найдётся XHR с курсами. Он добавит ~15 точек с курсами, обновлёнными за последние минуты. Склейка идёт по нормализованному адресу и расстоянию до 30–50 м. Выбор курса — по правилу «самый свежий». Для курсов только с marketportal временем курса считаем время его пакета. Дополнительно стоит хранить своё «последнее изменение значения», чтобы распознать курс, который не меняется днями. **Ожидаемое покрытие в Варшаве — 60–80 kantorów с курсом, датированным сегодняшним днём (примерно в 4–5 раз больше, чем 15 у одного kantor.live), из ~250 существующих.** В 12 крупных городах ситуация похожая. В остальных ~130 городах будут только marketportal и kantor.live с неизмеренной свежестью.

**Польша, координаты и часы.** Сначала берутся координаты kantor.live. Затем геокодер GUGiK UUG (ответ в EPSG:2180, нужно перевести в WGS84). Затем Nominatim 1 запрос в секунду с вечным кэшем. OSM нужен как подсказка для часов, если их нет у kantor.live и marketportal. Свободный текст часов у zlata.ws можно разбирать в последнюю очередь. kantorymapa.pl в MVP не нужен: точку без курса FR-15 всё равно не показывает. Он пригодится позже, если появится слой «kantory без курса».

## Архитектура в бесплатных лимитах: связывает CPU, а не запросы

На бесплатном тарифе Workers даёт **100 тыс. запросов в сутки, 5 Cron Triggers на аккаунт, 50 подзапросов и 10 мс CPU на один запуск**. Для cron-запусков действует ещё лимит в 15 минут по реальному времени, при этом ожидание сети в CPU не засчитывается ([CF Workers limits](https://developers.cloudflare.com/workers/platform/limits/)). Запросов хватает с запасом: горячий цикл (Минск + Варшава) — это около 12–14 запросов к источникам каждые 15 минут. Узкое место — разбор: HTML myfin весит 2,1 МБ, onliner — 2,9 МБ, JSON Беларусбанка по всей стране — 1,26 МБ. Уложится ли разбор каждого из них в 10 мс даже потоковым HTMLRewriter, не документировано, поэтому это нужно измерить. Отсюда вывод: **один cron-запуск каждые 15 минут ставит в Cloudflare Queues по сообщению на пару (источник, город), и обработчик очереди разбирает каждое сообщение в отдельном запуске со своим бюджетом CPU**. Queues доступны на бесплатном тарифе: 10 тыс. операций в сутки ([CF Queues pricing](https://developers.cloudflare.com/queues/platform/pricing/)). При ~15 сообщениях за цикл и ~3 операциях на сообщение выходит около 4,3 тыс. операций в сутки, то есть в лимит укладывается, но запас всего около двух раз. Запасной вариант — до пяти cron-расписаний со сдвигом, по одной группе источников на каждое.

В D1 бесплатно **100 тыс. записанных строк в сутки**, а при исчерпании запросы до полуночи UTC просто перестают выполняться ([CF D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/)). Поэтому писать нужно только изменившиеся курсы (upsert при изменении значения), а историю хранить агрегатами. Наивная запись «каждая точка × каждая валюта × 96 раз в сутки» только по Минску и Варшаве превысила бы лимит. KV с 1000 записей в сутки годится только для «последнего снимка» горячего города, на чтение для PWA ([CF KV limits](https://developers.cloudflare.com/kv/platform/limits/)). Остальные города обновляются по запросу. Это одна-три страницы источника внутри HTTP-запроса и блокировка, чтобы одновременные запросы не забирали один город дважды. Еженедельная пересборка (страницы отделений myfin, `filials_info`, геокодирование) идёт через Queues или Workflows с паузой не меньше 1 секунды между запросами ([CF Workflows limits](https://developers.cloudflare.com/workflows/reference/limits/)). Если разбор тяжёлый, её можно вынести в GitHub Actions публичного репозитория. Там неограниченные стандартные раннеры, а расписание — не чаще раза в 5 минут, с задержками и возможными пропусками. Запись в D1 идёт через REST `/query` ([GitHub events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows), [CF API: D1 query](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/)). Из остальных бесплатных площадок Vercel Hobby запускает cron только раз в сутки, у Render Free нет cron, Oracle требует карту, а Deno Deploy даёт 10 ч CPU в месяц. Ни одна не лучше связки Cloudflare + GitHub ([Vercel cron](https://vercel.com/docs/cron-jobs/usage-and-pricing), [Render free](https://render.com/docs/free), [Deno pricing](https://deno.com/deploy/pricing)).

Главный нерешённый вопрос — география. Беларусбанк прямо пишет, что его **платёжные** API для нерезидентов работают «только с белорусских IP-адресов» ([belarusbank.by](https://belarusbank.by/o-banke/for-developers/api-platezhey-dlya-biznesa/)). Zerkalo сообщало, что сайты Белинвестбанка, Белагропромбанка и Статусбанка не открываются из-за границы ([news.zerkalo.io](https://news.zerkalo.io/economics/11059.html)). Все проверки этого исследования шли с домашней машины и вернули 200. С серверов Cloudflare или GitHub (Azure, США) ни один .by-источник ещё не проверялся. Если источник отвечает только белорусским IP, смена хостинга не поможет. Единственный бесплатный выход — сборщик на устройстве в Беларуси, который отправляет данные в Worker по защищённому эндпоинту.

## Риски и что осталось проверить

Самый серьёзный риск — юридический и технический одновременно. **Условия использования (regulamin/ToS) не прочитаны ни у одного источника**, проверялись только robots.txt. Кроме того, внутренние JSON kantor.live и myfin не документированы и могут поменяться без предупреждения. Для личного некоммерческого проекта с одним запросом в 15 минут на город это приемлемо, но адаптеры будут ломаться. Поэтому нужен `/api/health` и оповещение о падении парсера. Качество данных тоже требует фильтров. Уже найдены мусорные курсы БелВЭБ (PLN 0,1/9), перепутанные координаты у onliner и разные соглашения об осях у Беларусбанка и МТБанка. Подписи myfin даны с точки зрения клиента, неясно время в списке zlata.ws, а метка marketportal одна на весь город. Наконец, в Польше нельзя честно обещать «полные» данные: около двух третей kantorów курс онлайн не публикуют.

## Заключение

Задача по двум странам оказалась несимметричной. В Беларуси проблема инженерная: данные почти полные, и вопрос только в том, как разобрать мегабайтные страницы в 10 мс CPU и пройдут ли запросы из-за границы. В Польше ограничен сам рынок, и никакой источник не превратит ~250 варшавских kantorów в 250 свежих плашек. Отсюда продуктовый вывод. В Польше интерфейс должен честно показывать возраст курса и его источник, а в выборе лучшего должны участвовать только курсы с датой. Расширять покрытие выгоднее точечно, через сети с собственными лентами вроде Tavex, а не через новые агрегаторы, которые собирают курсы с тех же сайтов.

Порядок работ после этого исследования такой. Первым делом на шаге 2 нужно запустить пробный воркер, который проверит доступность .by-источников и затраты CPU. От его результата зависит, останется ли вся система на Cloudflare или понадобится сборщик в Беларуси. Это единственная проверка, которая может поменять архитектуру. Остальные пункты из списка меняют только детали адаптеров.
